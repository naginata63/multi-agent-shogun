# /viewer-request — 視聴者リクエスト対応

## なぜこのスキルがあるか(2026-10-18 殿叱責)

殿「リクエスト対応実施」に、拙者は自chコメントを語で絞った一覧の**新しい40件だけ**を見て「未対応は1件」と言い、その1件に着手した。
殿「全部で何件あるか調べずこれをやり始めたのはなぜだ」「昨日わしが返信したやつは?」。
**親コメントしか見ず、返信の形で届いた依頼(告知コメント「切り抜いてほしいシーン大募集」への返信)と、殿の受付の印を丸ごと落としていた。**

## 手順(この順で・飛ばすな)

### 1. 全部取る(台本で)

```bash
cd projects/dozle_kirinuki && python3 scripts/request_inventory.py --pages 10
```

- 自chの全スレッドを新しい順に取り、**返信まで全部**読む(1ページ=100スレッド。10ページで約4か月)
- 自ch以外の依頼らしき物を、親コメント・返信の両方から拾う
- 殿が「リクエストありがとう」と返した物に **受付** の印
- 台帳 `context/request_ledger.json`(コメントID → 状態・メモ)と突き合わせ、台帳に無い物は **未登録**
- 出力 `work/requests/inventory_<日付>.json`。**取れた範囲(最古の日付・スレッド数)を必ず殿に言う**
- **殿(自ch)の返信も全部並べて読む。** 依頼の言い回しも殿の受付の言い回しも一つでない(「可能でしょうか」への「リクエストありがとうございます」、「只今制作中です」「好みのシーンありますか？」)。語の網だけに頼ると、殿が受けた依頼を落とす(2026-10-25 殿「他に返信したのなかった？」: 手探り企画のモノマネと、大富豪の雨乞いを落としていた)。`request_inventory.fetch()` で取り、自chの返信ごとに「何に返したか」を並べ、台帳に紐づかぬ物を一つずつ見る(`work/requests/own_replies_<日付>.json`)

### 2. 未登録を全部読んで台帳に入れる

- 状態は `済 / 一部済 / 対応中 / 未着手 / 要確認 / 対応不可 / 依頼でない` のどれか
- 「済」は自chの動画と突き合わせて決める(`work/requests/own_videos.json` の題名・制作管理板 `scripts/seisaku_board_page.py` の ITEMS)。思い込みで済にしない
- 印字を途中で切った一覧で判断しない(全件を見たか、件数で確かめる)

### 3. 着手の前に、殿に一覧と総数を出す

| 状態 | 件数 | 中身 |
|---|---|---|
| 未着手(受付あり) | n | 受付日・依頼主・場面 |
| 一部済・要確認 | n | … |
| 済・対応中・対応不可 | n | … |

- **殿の受付があり未着手の物**を古い順に並べ、「どれから・全部か」を殿に決めてもらう
- 受付の印が無い物(殿が返信していない物)は、作るかどうかも殿に聞く。勝手に作らない

### 4. 決まった物から制作へ

- 場面の時刻は、その回のコメント(全件取得)と自動字幕(1回だけ取得・IP BAN注意)で当たりを付ける
- `/manga-short-workflow` の **Phase 2(clip_editor で殿が頭尻)** から入る。依頼の台詞の場面を on、前後の見どころを off で並べる(前例: work/editor/short_kudo.json, req_norimono.json)
- 着手したら台帳の状態を「対応中」に、非公開アップしたら「済」(動画ID)に書き換える

## 掟

- **返信はしない**(殿がする)。依頼主への連絡を待ち事項・提案に書かない
- 公開状態を言うときは YouTube API で実測(memory: feedback_no_viewer_replies_check_publish_status)
- 全数は「取れた範囲」とセットで言う(memory: feedback_count_check_against_known_total)
