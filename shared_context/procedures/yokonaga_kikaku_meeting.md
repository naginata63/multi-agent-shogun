# 横長の企画を決める大会議(調べる→案を出す→崩す→採点→決める)

2026-10-22 の夜、殿は「横長動画さ、なにつくればいいんよ 結論出てないよね」「リセットまだ使ってないからコスト度外視で横長動画企画検討せよ勿論収益重視」と命じられた。この会議で出した案Aが「合流企画でたった一度『全員そろわなかった』黄昏の森」で、殿はすぐ「あんa制作開始」とされた。

翌々日、殿は「結構まとをえてたんとおもうんよ あのやり方」と言われた。夜の決定会議は、5夜続けて結論が出なかった。それに対し、このやり方で一晩で決まった。

- 台本: `.claude/workflows/yokonaga-kikaku.js`(Workflow の名前 `yokonaga-kikaku` で呼べる)
- 発表の例: `projects/dozle_kirinuki/analytics/dashboard/yokonaga_kikaku_20261023.html`

## 毎晩の自動(殿 2026-10-24「これなこれ毎晩やれるようにせよ」)

- `projects/dozle_kirinuki/scripts/autopilot/kikaku_meeting.py <日付>` を、夜の `night.sh` が材料の直後に裏で走らせ、最後に待つ。
  - 1:00 に始まり、約2時間かかる。朝 6:30 の1通までに終わる。上限は 4時間50分。
- 段取りは下の表と同じ。係の数も同じ(調べる5・6視点×4案・1案に3つの目・審査3・決裁・点検)で、最後に「発表の文」の係が1人加わる。
- **係の道具は Read と `scene_tools.py` だけ。** コメントは視聴者が書いた物ゆえ、任意のコマンドは走らせぬ。計算の要る数字(横長の表・日別収益)は、台本が先に `work/autopilot/<日付>/kikaku/longs.md`・`data.json` に出しておく。
- 決裁役は、前の晩までの決定(`work/autopilot/_yokonaga/decision.json`)と比べる。新しい数字か殿の返事が入った時、または今夜の案の方が数字で明らかに強い時だけ変える。
- 出す物:
  - 発表ページ `analytics/dashboard/yokonaga_kikaku_<日付>.html` と `yokonaga_kikaku_latest.html`。ひな形は `scripts/autopilot/kikaku_page_template.html`。
  - 朝のページの「横長の結論」とその URL。
  - `context/kikaku_yokonaga_<日付>.md`。
  - ntfy の1通。
- 大会議が落ちた晩は、軽い決定会議(`yokonaga_decide.py`)の結論が朝に出る。
- 配管だけを試す時は `--smoke` を付ける。係を最小にし、ページは `.smoke.html` に出す。

## いつ使うか

- 殿が「横長なにつくればいい」「企画検討せよ」と言われた時。
- 夜の決定会議(`scripts/autopilot/yokonaga_decide.py`)が何夜も同じ案を回し、決めきれぬ時。

夜の決定会議は軽い型である。提案者・反証者・決裁役の3人で毎晩回し、決めたことを次の晩へ持ち越す。この大会議は重い型である。エージェントは約40〜60人。数時間かかるゆえ、殿が費用を度外視と言われた時、または上限に余裕がある時に回す。

## 呼び方

```
Workflow({ name: 'yokonaga-kikaku', args: { date: '2026-10-22', background: '(今回の経緯。夜の会議で何が決まらず、何が弱いと言われたか)' } })
```

- `date` は、夜の自動の材料 `work/autopilot/<date>/materials_meeting.md` がある日付。
- 一時ファイルは `work/kikaku_scratch/<date>/` に書かれる。

## 段取りと、的を射た理由

| 段 | すること | 効いた点 |
|---|---|---|
| 1 調べる(5人並行) | 自chの横長の収益の作り / 他chの横長の勝ち筋 / 本家の素材の在庫と旬 / 殿の掟と退けた理由の全目録 / 過去の案の在庫 | 数字は必ず出所(ファイルとキー)付き。推測は「仮説:」で分ける。収益の芯(長尺は1000再生あたりショートの約22倍、新作の無い期間に日別収益が下がる)を最初に皆で共有する |
| 2 案を出す(6視点×4案) | 収益 / 見つけてもらう / ファンの需要 / 新しい型 / 旬と暦 / 続けて作れる柱 | **素材の実在を、案を出す者が自分で `scene_tools.py` を走らせて確かめる**(走らせた命令も書く)。確かめられぬ案は出させない |
| 3 まとめる | 同じ中身の案を束ね、殿の掟に明らかに触れる案を理由付きで落とす | 殿が退けた形・暦違い・1時間超・測れぬ量を、ここで先に機械的に落とす |
| 4 崩す(1案に3人) | 数字の裏付け / 殿の掟 / 作れるか(素材確認を自分で再実行) | 2人以上に崩された案は落とす。都合のよい切り取りを探させる。例: 新しい数字を伏せる・型の最低の回を伏せる・累計で型を読む |
| 5 採点(3人) | 収益重視 / 押したくなるか / 掟と作りやすさ。4項目を1〜10点 | 収益を2倍で足す。7日後の見込みは、似た自chの回の実数を物差しにした幅で書かせる |
| 6 決める(1人) | 1本に決める。「両方」「様子見」は禁止 | 構成(何分に何)・過去作と違う工夫・見込み・次点2本と切り替える時機・作る段取り・見切りの条件・殿に聞く事1つまで書かせる |
| 7 点検(1人) | 抜けた調査・裏の無い数字・掟の見落とし | 結論が揺らぐかを一言で |

台本の頭(CTX)には、殿の掟9か条を全員に配る。

- 内容: 問いを一言で / 暦 / 腐すラベル禁止 / 使い回し禁止 / 型は初速の推移で / 1時間超は維持率が落ちる / 素材は本家の横長本編のみ / AIが場面を選ばぬ / 推測の数字禁止。
- 掟が増えたら、台本の CTX にも書き足せ。

## 終わった後(台本の外で拙者がすること)

1. 結果を発表ページにまとめる(殿「分析結果のプレゼンもリッチにせい」)。
   - グラフ: 横長ごとの初速の推移(型で色分け)・維持率と尺・1本あたりの収益・日別収益と新作の印。
   - 会議の道のり: 何案出て、何案束ね、何案崩れたか。
   - 決めた案の構成・見込み・見切りの条件、次点。
   - 例は上の `yokonaga_kikaku_20261023.html`。
2. ntfy で殿へページの URL を送る。殿のお返事を待つ。作るか否かは殿が決める。
3. 結論は `projects/dozle_kirinuki/context/kikaku_yokonaga_<日付>.md` に残せ。案・崩れた理由・殿のお返事を書く。夜の会議が次に読む。
   - 10-22 の分はこれを怠った。ゆえに、この手順書と同じ日に書き足した。
4. 決めた案は `work/autopilot/_yokonaga/decision.json` の夜の決定会議にも渡し、毎晩ぶれさせぬ。
