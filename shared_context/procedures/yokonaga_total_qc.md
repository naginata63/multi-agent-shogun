# 横長の総点検の回し方 — 機械の測り1本+Sonnet の目付け3人

チーター軍団縦断(2026-10-25)で確立した。

- 前のやり方では、Opus の検査役9人を並列に立てていた。各自が Qwen3-ASR を CPU で読み込み(1本8GB)、5重になって 46GB を使い切り、OOM で将軍の座ごと全滅した(04:21)。
- その前にも、同じ9人で利用上限に当たり全滅していた。
- 2度目は約1億700万トークン・40分を使い、一人も仕上がらなかった。
- 殿「この仕組みいいんだがコストかかるな、押さえる工夫できるか？」→ この型にして「よい」。
- この型の実績: 1回の総点検は Sonnet 3人で約75〜85万トークン(前の約1/100)。1人あたり7〜14分で仕上がり、メモリ不足は一度も出ていない。

アップの可否を伺うのは、最終版に総点検をかけ、重い/中を0にした版だけ(`feedback_full_qc_final_version_before_upload`)。組み方の掟は `yokonaga_cards_quiz_build.md`。

## 使う物

| 物 | 場所(`projects/dozle_kirinuki/` から) |
|----|------|
| 重い処理の門番(同時に1本だけ・メモリ上限) | `scripts/heavy.sh [-m 8G] <command...>` |
| 機械の測り(全編を一度に) | `scripts/qc_machine.py <work> <out_vN> <動画名> [--adapter cheater]` |
| 目付けへの下知の雛形 | `shared_context/procedures/yokonaga_total_qc_eye_prompt.md`(リポジトリ直下) |
| 札の訂正ページ(殿が文言と読み上げを直して保存) | `scripts/cheater_card_editor.py --port 8139` |

`heavy.sh` は flock で1本ずつ並べ、`systemd-run --user --scope -p MemoryMax` で上限を掛ける。上限を超えた処理だけが殺され、PC 全体は落ちぬ(試し: 100M の上限で 300MB を取ると rc=137)。

## 手順

### 1. 組み上がったら、機械の測りを全編にかける

```bash
cd projects/dozle_kirinuki
timeout 2400 scripts/heavy.sh -m 6G python3 scripts/qc_machine.py work/<企画> out_vN <動画>.mp4 --adapter cheater
```

- 出力は `work/<企画>/qc_vN/machine.json`(summary と flags)。中間物は `qc_vN/machine/`(全編の音の float・YAVG・blackdetect・部品の表)に残り、二度目は使い回す。
- 測る物:
  - 全体の I/TP。
  - 部品ごとの I と、札とその前後の差。
  - 境目の前0.7秒の穴(-55dB)、札→札の継ぎ目の途切れ、境目のプツ音。
  - 札の尻の沈み。ただし最後の0.05秒(継ぎ目のフェード)は除く。
  - 元の語(STT)が頭尻をまたぐ所、尻のフェードが最後の語に掛かる所、hi の直後に次の語の頭が入る所。
  - 黒コマ(元動画の同じ秒にもある黒と、札の中のフェードは除く)と、境目近くの1〜4コマの明るさの跳ね。
  - 台本の字の禁句(約N分・チャット・メンバーの「さん」・半角の約物・約物の続き)、2行の釣り合い、行末の句点、自動の改行。
- 部品の表は `--adapter`(組立ごとの部品名→編集アプリの区間)で作る。別の企画で使う時は adapter を足す。無ければ `generic`(marks.json だけ・語の検査は無し)。

### 2. 機械が出した印は、将軍が確かめてから台帳に載せる

印は「見る所の目次」で、そのまま指摘にせぬ。チーター軍団では、印のほとんどが空騒ぎだった。

- **語の切れ**: 元の文字起こしの語の時刻はずれる。24件中18件は空騒ぎだった。
  - 完成品の区間を GPU の Qwen3-ASR で読み、語が最後まで入っているか確かめる。
  - 元の音を「候補の位置から先」で切って ASR に聞かせ比べ、最初の語が欠けぬ一番遅い位置を取る(`yokonaga_cards_quiz_build.md` §2)。
- **黒コマ**: 元動画の同じ秒を blackdetect で調べる(ゲームの暗闇の明滅は元からある)。
- **音量の差・I の端**: 掟の線をわずかに外れただけ(2.1 LU など)なら、境目を切り出して耳で判じる(手順7)。

### 3. コマの一覧(タイル)を作る

```bash
mkdir -p work/<企画>/qc_vN/tiles
scripts/heavy.sh -m 4G ffmpeg -nostdin -v error -y -i work/<企画>/out_vN/<動画>.mp4 \
  -vf "fps=1,scale=384:216,drawtext=fontfile=/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf:text='%{pts\:hms}':x=4:y=4:fontsize=22:fontcolor=yellow:box=1:boxcolor=black@0.7,tile=6x5" \
  -vsync vfr work/<企画>/qc_vN/tiles/t_%03d.jpg
```

- 1枚が30秒(1秒1コマ・6×5)で、2304×1080。テロップの字まで読める。
- 目付けはこれで見る所を決め、怪しい所だけ原寸のコマを取る(1人40枚まで)。

### 4. 目付け3人(Sonnet)を出す

- 範囲は章の扉の秒で、全編をほぼ3等分する(例: 0〜第3戦の扉 / 〜第7戦の扉 / 〜最後)。
- 雛形の { } を埋め、`Agent(subagent_type=general-purpose, model=sonnet, run_in_background=true)` で3人同時に出す。
  - 前の版の台帳(`qc_<前の版>/raw_eye*.json`)。
  - この版で変えた所(まず見る所)。
  - 殿が了承済みで、再び出さなくてよい物。
- 下知の要所:
  - 音声・画像のモデルを読み込ませぬ。音と札の字は測らせぬ(機械が測り済み)。
  - 1GB を超えそうな python は `heavy.sh` を通す。ffmpeg は2本まで。
  - 結果はすぐ `qc_vN/raw_eyeK.json` に書き、書き足させる(落ちても残る)。
  - 返事は件数と台帳の場所だけ(拙者の文脈を食わぬ)。
- 目付けが見るのは、機械に判じられぬ所だけ:
  - 重ね物が顔に被らぬか、足した※の注が無いか。
  - 前フリとオチ、絵の切れ目(別視点の数コマ・F3 の画面・暗転)。
  - 札の事実と敬称、各章でチートが実際に効く場面が映っているか。

### 5. 重い/中は、将軍(Opus)が自分で確かめてから判じる

- 目付けの「中」は、版ごとに揺れる(同じ所を前の版は軽・次の版は中と付けた)。語の切れは、ASR で確かめると切れていないことがある。
- 確かめた結果(コマ・ASR・測り)を台帳の `verified` に書き、重さを付け直す。
- 殿が了承した物(本家の画面の F3 など)は、次の版の下知の「了承済み」に入れる。

### 6. 直したら、変わった所だけを洗い出して確かめる

- 新しい `out_vN` で組み、部品(`seg/*.mp4`・`aud/*.wav`)の md5 を前の版と比べる。変わった部品が直した所だけかを見る。
- 区間を1本でも足す・分けると、後ろの部品の名と秒が全部ずれる。名ではなく中身(md5)で比べる。
- 直した所は将軍が ASR とコマで確かめ、全編に機械の測り(手順1)をかけ直す。
- 目付けの全編の検分をかけ直すかは、変えた量で決める。札や区間の中身を広く変えたら、かけ直す。1〜2か所の区間の頭尻だけなら、md5 で他が同じことを確かめて済ませ、その旨を殿に言う。

### 7. 聞こえぬ数字のために組み直しを重ねぬ

- 1回の組み直しは約15分。チーター軍団では、札→区間の音量差 2.1 LU(掟 2 LU)を消そうと仕上げを3度組み直し、上げるのを1時間近く止めた。
  - 殿「なにをしてんの？」。聞き比べを出すと「だれがわかるん？これ」。
- 掟の数字は、聞こえる不具合を防ぐための目安である。
  - 人が音量の差に気づく目安は、同じ音を続けて聞き比べた時で約1 LU、誰でも分かるのが約3 LU。
  - 読み上げの札からゲームの音の区間へ移るように音の種類ごと変わる境目では、2 LU 前後の差は場面の変化に紛れる。
- 掟をわずかに外れた時は、境目を切り出して(NVENC で書き出し)耳で判じ、分からねば「軽」として上げる。
- 組み直しが2回続いたら手を止め、殿に今の様子を先に言う。

## 費えの目安(チーター軍団・43分)

| | 前のやり方 | この型 |
|---|---|---|
| 目付け | Opus 9人・約1億700万トークン・未完 | Sonnet 3人・約75〜85万トークン・7〜14分/人 |
| 音と札の字の測り | 9人がめいめい作り直し | `qc_machine.py` 1本(LLM の費えなし・数分) |
| 文字起こし | CPU で5重(1本8GB) | 将軍が GPU で1本ずつ(`heavy.sh`) |

## してはならぬこと

- 検査役に音声・画像のモデルを読み込ませる。重い処理を門番(`heavy.sh`)を通さずに並べる。
- 9人のような大人数を Opus で並列に立てる。
- 機械の印や目付けの「中」を、確かめずに殿へ出す。
- 掟の線をわずかに外れただけの数字のために、殿を待たせて組み直しを重ねる。
