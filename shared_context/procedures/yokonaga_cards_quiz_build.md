「合流企画でたった一度『全員そろわなかった』黄昏の森」で確立した(2026-10-23)。
- 36分・8章。第1〜7版まで、毎版全編の品質検査を回して直した。
- 非公開アップは o2Y7XnEd1-A。

新しく横長を組む時は、この文書の決まりと検収に従え。各項目は「決まり → 確かめ方」で書き、(vN) は初めて指摘された版を表す。

実装の参照先:

## 0. 作る順と版の扱い

1. 台本(plan.json)を一つの正本とする。札・題・概要欄・チャプターは、すべてそこから作る。
2. 組むたびに新しい `out_vN/` を作る。作り置き(seg/frm/tts)の使い回しで、直しが効かなかった事故が二度あった。
   - (v4) TTS のキャッシュ名に速さが入っておらず、旧い速さの音が使われた。
   - 作り置きを使う時は、中身を決める値をすべてキャッシュ名に入れよ。
3. **手で後から当てた直しで出荷するな。** 第7版では TP の刈り込みを手で当てた。直しはスクリプトに入れてから組み直せ。
4. 台本に新しいキーを足したら、次の3か所を同じ変更で直せ。
   - 関数の引数
   - 章ループの kw
   - 台本
   - (v5〜v6) `band`・`chip_dur`・`door_t` が組立に届かず、黙って無視されて2版残った。
5. 確認用の配布は `ln` のハードリンクにし、版番号付きの名前(`gouryu_v7.mp4`)にせよ。リンクした後は元を書き直すな。

## 1. 札の音

| 決まり | 確かめ方 |
|---|---|
| 静止の札にはすべてBGMを敷く。文字を見せる札にはすべて読み上げを付ける(問いを読むなら答えも)(v1・v2: 無音の札・-28 LUFS の札) | 札ごとに ebur128 で測り、前後の本編との差が 2 LU 以内 |
| 読み上げは、wav ごとに ebur128 で I を測り、固定の増減 `volume=(目標−I)dB` でそろえる。目標は「最後の正規化の前の本編の中央値」(今回は -11.5)。短い TTS に loudnorm を掛けるな。長さによって届き方が変わり、3.7 LU ばらついた(v3〜v6) | 声の鳴る範囲だけを全札で測る。いちばん短い声と長い声を必ず含め、ばらつきは ±1 LU 以内 |
| BGMは一律に下げず、声をキーにした sidechaincompress で、読み上げの間だけ下げる(threshold 0.02・ratio 8・attack 20・**release 150**)(v3: 声とBGMの差が4dBしかなく、ASR が「合図→会津」と聞き違えた) | 声とそれ以外の差が10dB以上 |
| **sidechaincompress と amix(duration=first) は、短い入力で止まる。** 声・キー・最終の出力を `apad=whole_dur={dur}` で札の長さまで延ばせ(v4: 全31枚の札の尻が無音) | 全部品で、音と映像の長さの差が0.05秒以内 |
| 札の tail は、release + BGM の尻のフェード + 0.3秒以上にする。説明の札は 0.9(v5・v6: 札の尻が沈んだ) | 札の尻0.7秒を10msごとの RMS で測り、-50dB を割らない |
| 効果音と声を重ねない。vdelay は効果音が減衰しきってから(問いは 0.9 で sfx 0.3、答えは 2.0 で sfx 0.35)(v2〜v4 の3版残った)。※場面転換SEの「1.5が標準」(feedback_se_volume_default)とは別物。読み上げの下で鳴る札のSEの話 | 声の頭0.1〜0.4秒で、声がそれ以外より6dB以上大きい |
| 札から札へ曲が続く所は、尻と頭のフェードを0.05秒以下にする(`bgm_fout`/`bgm_fin`)(v2〜v6: 決まり→扉で0.2秒途切れた) | 境目±0.5秒を10ms RMS で測り、-50dB を割らない |
| **曲そのものの休みが札の頭や尻に来ると、絵の切れ目で音が消える。** 曲の休みの表を作り、札の頭0.35秒と「読み終わり〜札の尻」に休みが来ない所まで開始位置を送れ(`_rest()` は0.3秒窓の休みの濃さで測る。v7: 尻0.7秒・0.2秒連続だけ見ると、打音で割れた休みや窓の手前から始まる休み、問いの考える間の休みをすり抜けた)。休みの多いスタッカートの曲(710_なんでしょう は約19秒ごとに0.24〜0.4秒休む)は、札の多い動画に選ぶな(v3・v6) | 全編を10ms刻みで走査し、部品の境目の前0.7秒で -55dB 未満が0.15秒を超えない |
| 章の頭の札(決まり・扉・締め)は vdelay=1.0。チャプターは切り上げて書くゆえ、飛ぶと読み上げの頭が欠ける(v4) | 各チャプターの秒が、その札の読み上げの始まりより0.3秒以上前 |
| 読み上げの文は画面の文と別に持つ(`answer_voice`・`voice`)。括弧を外し、紛れる語はかなに開く(間→あいだ、越し→ごし)。速さは1.05。1.15では「という合図」がつながった(v3) | audio_query の kana と、声だけを ASR に掛けた結果 |

BGMの出どころ: 今回は `assets/bgm/710_なんでしょう_KK.mp3`。次は `assets/epidemic/` を優先して選べ(project_epidemic_sound)。休みの少ない曲を選べ。

## 2. 区間の切り方

| 決まり | 確かめ方 |
|---|---|
| 切れ目は、幅0.1秒以上・-30dB以下の谷に置く。さらに語単位の STT(Qwen3-ASR)で、文が言い切られていることと、次の語の頭が入らないことを確かめよ。谷だけで決めると「…やってくると」で文が終わる(v2〜v6) | 全区間の頭尻を STT と10〜20ms RMS で照らす |
| 尻のフェードは、最後の語が終わってから始まるようにする(fade_out ≤ hi − 語の終わり)。既定は頭0.05・尻0.08。歓声が続く所は、谷の中に収まる0.03〜0.06のフェードで切る。長いフェードは「ございます」の「ます」を飲む(v1 一律0.3・v4〜v6) | 最後の語の大きさが、元の音から3dB以内 |
| 本編の区間の映像にはフェードを掛けない。継ぎ目は切り替えだけにし、音だけ短くフェードする。黒からのフェードは、題・扉・決まり・締めの札のみ(v2・v4: 継ぎ目に黒コマ) | 全体に `blackdetect=d=0.02:pix_th=0.1` |
| 尻に別視点が1〜数コマ挟まる時は、hi を切り替わりの手前にする。語尾を残したい時は `vhold`(絵だけ tpad で止め、音は hi まで流す)(v4〜v6) | 頭尻0.35秒の YAVG を signalstats で取り、1〜4コマだけの跳ねを拾う |
| 元動画で続く場面は1区間にまとめる。割ると継ぎ目で音が抜け、小札が出直す | 同じ動画で、前の hi と次の lo が同じ秒の所を洗う |
| 時間が1分超飛び、間に状態が変わった時(全員死亡・合流・移動)は、説明の札を挟む。札には時間の言葉と、何が変わったかを書く。**時間は「約N分後」と書くな**。動画の秒の差は撮影の実時間ではない(殿 2026-10-24)。少しして(5分未満)/しばらくして(5〜10)/だいぶ経って(10〜20)/かなり経って(20超)のように、雰囲気で長さを伝える。結末の後の出来事(ギブアップ→飛んだ)も説明の札で示す。でないと、そろわなかった回が合流したように見えた(v1) | 章の最後の区間を音なしで見て、結末の印象が章題と同じか |

## 3. 連結と仕上げ

- 映像は concat demuxer で copy する。音は、部品ごとにコマ数ちょうどへ切り揃えた PCM をつなぐ(feedback_concat_copy_audio_drift)。
  - ※`context/ffmpeg_rules.md` の「異なる動画は filter_complex concat」は OOM の元ゆえ使うな。
- 仕上げの順:
  1. 全体の I を ebur128 で測り、`volume=(-14−I)dB` の固定の増減を掛ける。
  2. その後に `aresample=192000,alimiter=limit=0.66:level=false:attack=1,aresample=48000` を掛ける。
  - loudnorm は使うな。`linear=true` でも、TP が届かぬと黙って動的に落ちる。v7 では区間ごとに -2.4〜-6.5dB と4dB揺れた。
  - AAC にすると山がはみ出すゆえ、上限は目標(-2.5)より低めに取れ。
- 検収は AAC に書き出した後の完成品で行う。
  - `ebur128=peak=true` で、I が -14.0±0.3、TP が -2.5 以下であること。
  - 部品ごとに元の音と相互相関を取り、lag=0 であることを6本以上で確かめる。

## 5. 重ね物(出典・手段の小札・注釈)と、本家の画面の禁止域

- 上端の名前帯
- 下端140px(本家テロップ・ホットバー)
- 右上 y≈20〜130(効果アイコン・通知)
- 動く名札と顔

**空いている所:**
- 左上の名前帯のすぐ下(y≈105〜180)
- 上中央(y≈110〜160)

位置で避けられぬ名札・顔は、出す時間を短くして避けよ。

| 決まり | 確かめ方 |

## 6. 止め絵クイズ(合図クイズ)

- **止める秒(`freeze_t`)の選び方:**
  - 音の谷の中に置く。
  - 合図がそろって映っているコマを選ぶ。
  - カーソル・答えのテロップが無いコマを選ぶ。
  - 止める前の区間は2秒以上にし、合図を作った一言を一度は聞かせよ。
- **答えのネタばれを防ぐ:** 答えの要の語(人数・場所・「合流した」)で、章の頭から止める秒までを全部調べよ。調べる先は STT・本家の字幕・小札・扉の小書き・ヒント。
- **答えの札の位置: 止めた所から本編を流し、みんなの反応・読み解きを見せてから答えの札を出せ**(殿 2026-10-24「解答だすの早い 間にみんなの反応があってから答えにしたい」)。
  - v8〜v13 で一度「問いのすぐ後」にした。検査役の「答えが二度出る」という指摘を受けてのことだったが、殿に戻された。
  - 本編に反応が無い章だけ、問いのすぐ後でよい。
  - 答えの読み上げは短くし、本人の言葉の繰り返しにしない。
  - 止め絵の直後に同じ画面が数コマ続く所は、`resume_skip` で飛ばせ。
- **答えの帯:**
  - 問いの帯と同じ高さ以上にする(`banner_h` → `answer_card(min_h)`)。帯の範囲はぼかしてから、alpha 245 以上の地を敷け(v4〜v6: 低い答えの帯の下から名札がのぞいた)。
  - 問いと答えの札は、黒からのフェードを掛けない(`vfade=False`)。
- **文言:**
  - 問いの主語は、扉の決まりと同じ言葉で書く。
  - ヒントは、問いに書いていない別の手がかりにする。
  - 答えの中の事実(誰・何人・どこ)は、見せた区間か説明の札で全部たどれるようにせよ。

## 7. 品質検査の回し方

- **検査役の立て方(Workflow):**
  - 章ごとに1人(中身・区間の頭尻・重ね物)。
  - 横断の「札の改行(全数・原寸)」「音」を、初版から置く。
  - 4秒刻みのシートは見る所を決める目次にだけ使え。判定は次の実測で行う。
    - 原寸のコマ。
    - 境目の前後を30fpsで全コマ。
    - YAVG の跳ね。
    - 10ms RMS。
    - Qwen3-ASR。
  - 「OK」も実測値付きのみ認める。
- **指摘の台帳:**
  - 指摘は ID 付きの台帳にする。
  - 次の版の検査役に前版の台帳を渡し、全件の直り・未直りを答えさせよ。
  - 「直した」と言う前に、部品を前版と `cmp` せよ。同じなら、直しが届いていない。
  - 台本で直る物と、スクリプトで直す物を振り分けよ。スクリプト側の指摘は持ち主を決めないと何版も残る(v2〜v6)。
- **直しの影響:**
  - 共通関数(card/clip/_banner/_wrap)を直したら、それを通る部品を全数測り直せ。直しは別の所を壊す(v4 のダッキングで、全札の尻が無音になった)。
- **アップの可否を伺う前:**
  - 最終版に全編の総点検を回し、重い/中が0件であることを確かめよ。直した所だけの自己確認で出すな(殿 2026-10-23)。

## 8. 上げる

1. 題・概要欄は、同じ out_vN の title.txt / description.txt を使う(`gouryu_desc.py`)。
   - チャプターは切り上げ、60分以上は h:mm:ss で書く。
   - 各章の直下に、元動画の日付と ?t= 付きリンクを置く。
   - 公式チャンネルとガイドラインを入れる。
2. `youtube_uploader.py upload ... --privacy private` で上げ、`thumbnail <id> <16:9 jpg>` でサムネを付ける。
3. videos.list で読み戻し、次を確かめる。
   - 状態・題・概要欄・タグ・サムネ。
   - 尺は処理が済んでから確かめよ。直後は P0D と出る。
4. ntfy で殿へ知らせ、確認ページにリンクを載せる。公開は殿の専権。
